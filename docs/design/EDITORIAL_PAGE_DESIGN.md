# 个人工作台：编辑杂志风页面与交互设计

## 设计阶段结论

这不是一个“带有杂志皮肤的 Todo List”，而是一份每天打开的个人编辑台：课程是当日版面中的固定时刻，计划是需要推进的行动，岗位是持续更新的求职稿件，简历是可追溯的档案，备忘是尚未编辑完成的边角稿。

风格参考中的“禁止项”优先于其 Token 字典中出现的冲突示例。因此本设计严格采用：暖米色背景、柔和黑文字、纯单色层次、无阴影、无渐变、无彩色状态、无大圆角；红色按钮示例不采用。

## 一、视觉方向

### 1. 视觉命题

**今日版面 / The Daily Desk**：每次进入首页，像打开一张只为今天编辑的个人工作报纸。大标题负责回答“今天是什么”，时间脊负责回答“什么时候发生”，细线和留白负责让信息保持可读。

唯一的视觉冒险是“日记簿时间脊”：课程和面试沿一条细竖线排列，线上的时间点代表真实事件，不是装饰。其他模块保持安静，让这一条结构线成为产品记忆点。

### 2. 单色 Token

| 角色 | 值 | 用法 |
|---|---|---|
| 页面背景 | `#F9F8F6` | 全局暖米色，不使用纯白或冷白 |
| 主文字 | `#1C1C1C` | 标题、重要内容 |
| 次要文字 | `rgba(28,28,28,.60)` | 说明、辅助信息 |
| 弱文字 | `rgba(28,28,28,.40)` | 标签、时间、占位信息 |
| 细线 | `rgba(28,28,28,.10)` | 分隔、网格、输入框初始状态 |
| 深底 | `#1C1C1C` | 反转按钮、底部操作区，使用暖米色文字 |

不使用蓝、红、绿、黄等强调色。优先通过文字、符号、线型和位置表达状态：`高优先级`、`逾期`、`已完成`，而不是彩色徽章。

### 3. 字体

- 标题：`Iowan Old Style, Noto Serif SC, Source Han Serif SC, STSong, serif`，正常字重，紧凑字距。
- 正文：`Microsoft YaHei UI, Segoe UI, sans-serif`，`14–16px`，至少 `1.7` 行高。
- 数据与时间：`Bahnschrift, Consolas, ui-monospace, monospace`，用于时间、周数、版本号和状态标签。
- 斜体只用于副标题、引导语或轻量注释，不用来表达状态。

### 4. 形状、线和动效

- 结构全部使用 `border: 1px solid rgba(28,28,28,.10)` 和底部细线。
- 默认 `border-radius: 0`；不使用胶囊标签、大圆角卡片或阴影。
- 不使用渐变、背景图案、玻璃态和装饰性几何图形。
- 链接使用从右向左展开的下划线；hover 不移动文字本体。
- 面板切换使用 `opacity` 或 `clip-path` 的短暂过渡，默认约 200–350ms；尊重 `prefers-reduced-motion`。
- 按钮采用黑底米字或透明底黑字的反转关系，只有 hover 时反转，不改变色相。

## 二、全局信息架构

### 1. 可收缩左侧导航

桌面端使用固定左侧导航，不把主导航压在页面内容上方。侧栏默认展开，用户可以用箭头按钮让它沿左边滑出；收起后，页面左边缘保留一个 `› 展开导航` 入口。

```text
┌──────────────┬───────────────────────────────────────────────────────────────┐
│ 个人工作台   │  TODAY / 今日                                                  │
│ PERSONAL DESK│ 今天，从重点开始                                               │
│              ├───────────────────────────────────────────────────────────────┤
│ 首页         │ 12 列内容版面                                                  │
│ 课表         │                                                               │
│ 岗位投递     │                                                               │
│ 简历         │                                                               │
│ 计划         │                                                               │
│ 设置         │                                                               │
│              │                                                               │
│ ‹ 收起导航   │                                                               │
└──────────────┴───────────────────────────────────────────────────────────────┘
```

- 品牌位于侧栏顶部：衬线字“个人工作台”，下方小号 `PERSONAL DESK`。
- 导航使用纵向文字列表；当前页面使用下划线和 `#1C1C1C` 加深，不使用填充胶囊。
- 侧栏底部用 `LOCAL / OFFLINE` 文字表示本机状态，不使用绿色圆点。
- 收起/展开使用 260ms 左右的横向位移动效；状态记忆在当前浏览器中，刷新后保持。
- 移动端侧栏覆盖内容区，仍然通过同一个箭头入口收起/展开；切换页面后自动收起。

### 2. 页面共同骨架

```text
固定左侧导航
    ↓
页面 eyebrow（小号大字距标签）
页面 H1（衬线、紧凑、单一主命题）
一行说明 / 日期 / 页面级动作
    ↓
12 列内容网格，区块之间使用宽留白和细线
```

内容容器：`max-width: 1280px; margin: auto; padding: 0 24px / 48px`。

桌面端使用 12 列网格，主区块之间 `gap: 48–96px`；工具型列表可以比宣传页更紧凑，但不牺牲行高和边界留白。

### 3. 全局交互语言

- “新增”统一写成具体动作：`新增课程`、`＋ 新增一行`、`新增计划`、`上传版本`。
- “保存”表示已经写入本地数据；成功后显示一行内联状态 `已保存 · 刚刚`，不使用无上下文的“成功”。
- 删除按钮写明对象：`删除这条课程`、`删除岗位`。
- 删除、整体恢复、物理删除文件必须二次确认；确认文案说明影响范围。
- 列表行点击打开右侧详情抽屉；键盘 focus 时操作按钮始终可见，不能只依赖 hover。
- 失败信息说明原因和下一步，例如“数据目录不可访问，请重新连接原目录”，不写“出了点问题”。

## 三、首页：今日版面

### 页面职责

只回答：“今天最值得我先看什么？”不展示其他模块的完整列表。

### 结构

```text
TODAY / 个人工作台
今天，9 月 4 日                         [本机 · 离线]
一张给今天的版面，留出足够空间做重要的事。
──────────────────────────────────────────────────────────────
│  今日课程（5列）                 │ 今日行动（7列）          │
│                                  │                          │
│  09:00  ─ 课程                   │ 01  高优先级计划          │
│  10:30  ─ 课程       日记簿时间脊 │ 02  普通计划              │
│  14:00  ─ 面试                   │                          │
──────────────────────────────────────────────────────────────
│ 快速备忘（4列） │ 近期面试（4列） │ 需要收尾（4列）          │
```

### 交互

- 点击课程行进入课表，并定位到对应教学周。
- 点击计划行直接切换完成状态；编辑动作进入计划详情抽屉。
- 快速备忘只有一条底线输入和一个文字按钮 `记下`，回车即可保存。
- 备忘列表项提供 `转成计划`，转换时只补充截止日期、优先级和分类。
- 近期面试显示未来 7 天；点击进入对应岗位详情。
- “需要收尾”显示逾期计划和未来 7 天高优先级计划，每一项显示原因文字。

### 首页状态

- 无课程：`今天没有课程安排`，动作 `查看本周课表`。
- 无计划：`今天没有需要推进的计划`，动作 `新增计划`。
- 无摘要：`未来 7 天没有需要特别关注的事项`。
- 本地服务未启动：整页显示启动提示，不显示空数据。
- 数据读取失败：保留页面标题，显示错误原因和 `重新读取`。

## 四、课表：周视图

### 页面职责

展示按学期和教学周重复的课程安排，不把课程伪装成任务。

### 结构

```text
WEEK / 2026 秋季学期                 [切换学期] [新增课程]
第 2 教学周 · 2026.09.07 — 09.13     [上周] [本周] [下周]
──────────────────────────────────────────────────────────────
时间       周一       周二       周三       周四       周五 ...
08:00      ─────────  ─────────             ─────────
10:00      课程名称              课程名称
```

- 周视图是主视图；不提供月视图。
- 星期标题显示日期和单双周规则。
- 课程块只有细边框和文字，不使用彩色填充。
- 当前日使用更深的外框和 `TODAY` 标签，不使用颜色。

### 交互

- 学期选择改变教学周计算和课程集合。
- `上周 / 本周 / 下周` 改变视图，不修改数据。
- 点击课程打开编辑抽屉；新增课程使用同一表单。
- 表单字段：课程名称、星期、开始/结束时间、地点、起止周、每周/单周/双周、老师、备注。
- 删除课程必须在抽屉中确认。
- 不提供临时调课入口；页面明确提示“第一版课程按固定教学周重复”。

### 课表状态

- 未设置学期：主区显示 `先设置一个学期，系统才能计算教学周`。
- 当前周无课：显示空周网格和 `本周没有课程安排`。
- 时间冲突：保存时阻止完全重叠的同日课程，提示冲突课程名称和时间。
- 学期日期无效：停留在表单并指出具体字段，不清空已填写内容。

## 五、岗位投递：求职档案

### 页面职责

让用户知道每个岗位现在处于哪一阶段、下一件值得做什么，以及当时使用了哪份简历。

### 列表结构

```text
PIPELINE / 求职进展
岗位投递                                      [＋ 新增一行]
搜索公司、岗位或备注   阶段：全部   方向：全部   渠道：全部   简历：全部
──────────────────────────────────────────────────────────────────────
#  公司       岗位名称       城市    投递渠道   投递日期   方向   阶段   简历
01 公司名     岗位名称       上海    Boss       2026.09.03 AI Agent 已投递 …
02 公司名     岗位名称       北京    官网       2026.09.01 RAG      一面   …
```

- 使用编号和细线建立档案感，不使用彩色徽章；表格在容器内横向滚动，不撑宽页面。
- `＋ 新增一行` 插入一条草稿行；公司、岗位、城市、渠道、方向可直接输入并从历史建议中选择，阶段和简历使用下拉，日期点击打开原生日历。
- 文本单元格按 Enter 可保存当前行，修改后才启用“保存本行”；“详情”管理阶段历史/面试，“编辑详情”补充岗位链接和备注。
- 阶段以文字和小号等宽字显示：`待投递 / 已投递 / 笔试 / 一面 / …`。
- 逾期或临近面试通过文字 `面试 · 3 天后` 表达，不单靠颜色。

### 详情抽屉

详情分为四段：

1. 基本信息：公司、岗位、方向、地点、渠道、链接、投递日期。
2. 当前阶段：阶段选择器和最近更新时间。
3. 招聘阶段时间线：从发现到当前的历史记录。
4. 面试安排与简历引用：轮次、时间、方式、结果、备注、使用的简历版本。

### 交互

- 列表支持搜索、阶段筛选、方向筛选、渠道筛选和最近更新时间排序。
- 修改阶段立即追加一条历史记录；不覆盖旧记录。
- `添加面试` 表单包含轮次、时间、方式、地点/会议说明、结果、备注。
- 面试可以编辑和删除；删除需要确认。
- `打开岗位链接` 在新标签页打开，并在按钮旁明确标注“离开本地工作台”。
- 选择简历版本时显示方向、版本和文件名，例如 `AI Agent · v3 · resume.pdf`。
- 删除岗位前明确说明会同时删除该岗位的阶段历史和面试记录，不删除被引用的简历文件。

### 岗位状态

- 无岗位：`还没有求职档案`，副文案 `从一个真正想投递的岗位开始`。
- 无面试：`暂无面试安排`，动作 `添加面试`。
- 简历文件缺失：保留版本引用，显示 `文件缺失 · 重新关联`。
- 链接为空或格式不合法：保存前在字段下方提示，不跳转页面。

## 六、简历：版本档案

### 页面职责

管理“求职方向”和“具体简历版本”两个不同概念，让岗位引用可追溯。

### 结构

```text
ARCHIVE / 简历档案                         [新建简历方向]
──────────────────────────────────────────────────────────────
AI Agent                                      RAG
适用于 Agent / 应用工程                       适用于检索增强
v3  当前版本                                  v2  当前版本
v2  2026.08.21                                v1  2026.08.12
v1  2026.08.02                                [上传版本]
```

- 简历方向作为一级档案标题。
- 版本作为底部细线列表，不嵌套圆角卡片。
- 当前版本通过文字 `当前版本` 和底线标识，不使用绿色徽章。

### 交互

- 新建方向：名称、求职方向、备注。
- 上传版本：版本名称、文件、版本备注；上传完成可设为当前版本。
- 点击 PDF 版本，在右侧预览抽屉显示；Word 版本使用 `打开文件`，不承诺 App 内预览。
- 每个版本提供 `设为当前`、`归档`、`下载`、`删除`。
- 已被岗位引用的版本只能归档，不能物理删除；详情显示“被 N 个岗位引用”。
- 点击岗位引用数量可跳转岗位列表并按该版本筛选。

### 简历状态

- 无方向：`还没有简历档案`，动作 `新建简历方向`。
- 有方向无版本：`这个方向还没有文件`，动作 `上传第一版`。
- 文件缺失：`记录还在，但文件不在数据目录中`，动作 `重新关联文件`。
- 上传失败：保留表单字段，说明文件类型、大小或内容校验原因。

## 七、计划：行动日记

### 页面职责

管理有明确日期和完成结果的行动，不承载课程重复规则，也不承载岗位本身。

### 结构

```text
ACTIONS / 行动日记                         [新增计划]
今日   2026.09.04                          [全部] [逾期] [已完成]
──────────────────────────────────────────────────────────────
□ 09:30  准备一面项目案例        高优先级   求职
✓ 14:00  完成课程阅读             已完成     学习
──────────────────────────────────────────────────────────────
本周
□ 09.06  整理 RAG 项目评测结果               求职
```

- 用 `□ / ✓` 表达未完成/完成，用文字表达优先级和逾期。
- 今日和本周是主入口，逾期与已完成是辅助筛选。
- 计划行 hover 只加深细线和下划线，不移动整行。

### 交互

- 新增/编辑计划使用底线输入和浮动标签：标题、开始日期、截止日期、可选时间、优先级、状态、分类、备注。
- 点击勾选直接完成；再次点击可恢复为进行中，但需要保留更新时间。
- 日期范围覆盖今天的跨日计划显示在今日视图。
- 逾期计划在列表顶部以 `逾期 · 截止 09.03` 文字说明。
- 搜索只搜标题和备注；筛选不改变数据。

### 计划状态

- 空列表：根据当前筛选显示具体引导，例如 `今天没有待完成计划`。
- 逾期：页面顶部显示逾期数量和最早截止日期。
- 保存失败：不关闭抽屉，字段值保留。
- 删除：二次确认，说明删除不可从列表恢复，但完整备份可恢复。

## 八、快速备忘

### 页面职责

承担“先记下来”的入口，不强迫用户在灵感刚出现时填写完整计划字段。

### 交互设计

- 首页始终可见一条底线输入：`突然想到什么？`。
- 支持 Enter 保存；不支持多行复杂编辑。
- 保存后显示 `已记下 · 可稍后整理`。
- 备忘行操作为 `转成计划`、`归档`、`删除`。
- 转换抽屉只要求截止日期、优先级和分类；标题默认取备忘内容。
- 转换成功后原备忘显示 `已转为计划`，不再出现在未处理列表。

## 九、设置：本地档案

### 页面结构

```text
LOCAL / 本机数据
数据目录
E:\\…\\Personal Workbench Data                 [复制路径]
──────────────────────────────────────────────────────────────
完整备份
导出全部记录和受管简历文件                      [导出备份]
从备份整体恢复                                  [选择备份]
```

### 交互

- 导出按钮使用明确文字 `导出完整备份`，下载后显示文件名和时间。
- 导入前显示备份创建时间、记录摘要和“当前数据将被整体替换”。
- 恢复前要求确认；恢复中显示阶段：`校验文件 → 暂存文件 → 替换数据 → 验证结果`。
- 恢复成功显示 `已恢复 · 共 X 条记录 · Y 个简历文件`。
- 恢复失败显示原因，并保留当前数据不变；如果已有安全副本，提供其位置。

## 十、响应式策略

### 桌面（≥ 1100px）

- 固定左侧导航，默认展开；收起后主内容回到全宽。
- 12 列网格。
- 首页课程 5 列、行动 7 列；下方三个 4 列区块。
- 岗位表格保留全部列，详情使用右侧 5 列抽屉。

### 平板（700–1099px）

- 左侧导航收窄到约 224px，仍可一键滑出；收起后内容回到全宽。
- 12 列变成 6 列；首页上下堆叠主要区块。
- 岗位表格收起低频列，详情抽屉占 6 列。

### 手机（< 700px）

- 左侧导航覆盖内容区，使用箭头按钮开关；切换页面后自动收起。
- 首页按课程 → 行动 → 备忘 → 摘要顺序单列。
- 课表允许横向滚动，日期标题固定在视口上方。
- 岗位表格保留横向滚动，单元格仍可直接编辑；操作列保持在表格末端，详情抽屉全宽显示。
- 所有表单单列，按钮全宽或右对齐。

## 十一、从现有第一版 UI 到 Editorial 的重构清单

现有实现已经具备业务流程，但视觉上仍是通用后台风格。下一次 UI 实施必须完成：

1. 删除彩色状态色，将优先级、阶段和完成状态改为单色文字/符号/线型。
2. 删除阴影和大圆角，将卡片改为细线分区。
3. 将深色侧栏改为暖米色、可收缩的固定左侧导航。
4. 将所有页面标题和区块标题改为衬线字体。
5. 将按钮改为具体文字动作和 hover 下划线/反转反馈。
6. 将输入框改为底线样式并加入浮动标签。
7. 用“今日版面”和“日记簿时间脊”替代通用统计卡片视觉。
8. 保留现有本地 API 和业务数据行为，不因视觉重构扩大产品范围。

## 十二、实施前自检

- [x] 页面只使用暖米色与柔和黑的单色体系。
- [x] 没有阴影、渐变、背景图案和大圆角。
- [x] 标题使用衬线，正文使用无衬线，正文行高至少 1.7。
- [x] 状态不只依赖颜色，文本和符号能够独立表达。
- [x] 按钮写清楚动作，hover 使用下划线或黑/米反转。
- [x] 空、加载、保存中、失败、目录不可访问、文件缺失和恢复失败均有明确反馈。
- [x] 键盘可操作，focus 可见；减少动画时仍能完成所有路径。
- [x] 桌面、平板和手机没有不可预期的横向溢出。
- [x] 视觉重构不修改课程、岗位、简历、计划和备忘的业务边界。
